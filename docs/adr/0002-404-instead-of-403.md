# ADR 0002 — 404, not 403, for another user's resource

Status: accepted · recorded 2026-11-22 (decision taken in the initial commits)

## Context

Every category, transaction and budget belongs to one user (through `Category.user_id`). A
request for an id that exists but belongs to someone else could answer 403 Forbidden or 404 Not
Found.

## Decision

Answer 404, with the same body as for an id that does not exist.

## Consequences

- The API never confirms that a resource id exists for another user, so ids cannot be probed.
- Every service scopes its queries by `Category.user_id` and raises `NotFoundError` for both
  cases. Category lookups go through `services/categories.get_owned` (also used when creating a
  transaction or setting a budget); deleting a transaction checks the owner directly; lists and
  reports filter with a join on `Category.user_id`.
- Every endpoint has a user-isolation test with the `alice` and `bob` fixtures (AGENTS.md,
  Testing), and the reviewer subagent checks for it.
